# План развития сайта «АвиаТехноСофт»

## Текущая ветка: полный сайт на WordPress (08.10.2026)

Владелец отказался от схемы «статический сайт + WordPress в `/news/`» из-за невозможности запустить существующую установку `/news/`. Рабочих новостей и медиа для переноса нет. Новая цель — один WordPress в корне домена, тема `wordpress/ats-site`; инструкция [wordpress-full-site.md](../docs/wordpress-full-site.md). Исторический план ниже относится к предыдущему варианту.

| Локальная проверка | Тема активирована на новом WordPress, пройдены страницы, новости, четыре формы и мобильное меню | владелец подтвердил, что сайт в LocalWP работает; состав проверок не уточнён |
| Тестовый хостинг | Корневой WordPress работает без 403 и ошибок HTTPS, письма приходят | ядро установлено в `/www/aviatechnosoft.ru/`; главная даёт 403, вход зациклен, системные ресурсы загружаются по HTTP |

### Текущие блокеры и порядок проверки на хостинге

1. Подтвердить, что `/www/aviatechnosoft.ru/` — корень и для `aviatechnosoft.ru`, и для `www.aviatechnosoft.ru`, а показанная таблица опций относится к базе и префиксу **этой** установки из `wp-config.php`. Не публиковать конфигурацию или реквизиты базы.
2. Проверить `WP_HOME`, `WP_SITEURL`, `COOKIE_DOMAIN`, `FORCE_SSL_ADMIN` в серверном `wp-config.php`. В показанной таблице `siteurl` и `home` равны `https://aviatechnosoft.ru`, тогда как хостинг переводит вход на `https://www.aviatechnosoft.ru/wp-login.php?attempt=1`. После резервной копии согласовать адреса с фактическим каноническим доменом.
3. Устранить генерацию системных CSS/JS WordPress по `http://www.aviatechnosoft.ru/...` на HTTPS-странице. Если эффективные адреса уже верны, проверить с хостингом передачу признака HTTPS в PHP (`HTTPS`/`HTTP_X_FORWARDED_PROTO`) и исключение страницы входа из кэша; затем повторить вход в чистой сессии.
4. Отдельно установить причину 403 на главной: проверить индексный `index.php`, настройки главного файла каталога, `.htaccess`, права и журнал веб-сервера. Доступность прямого `wp-login.php` не доказывает, что `/` настроен правильно.
5. После восстановления входа установить только `ats-site-theme.zip`, активировать тему и проверить страницы. Затем настроить почту, старые адреса, юридический текст и выполнить проверки перед публикацией.

**Решение по переносу:** файлы ядра WordPress хостинга не заменять содержимым `C:\Users\niokr\Local Sites\atsru\app\public`. Простое копирование не перенесёт базу данных, а локальный `wp-config.php` содержит неподходящие параметры; рабочих новостей и медиа для полного переноса LocalWP нет. Сохранить возможность отдельного полного переноса только если позже появится реальный контент.

Рабочий план для изменений в этом репозитории. Решения, проверки и открытые вопросы фиксируются в [site_worklog.md](site_worklog.md). Статусы: `—` · `в работе` · `готово` · `ждёт проверки` · `отложено`.

## Правила работы

- Изменения основного сайта ведём в `index.html`, `assets/` и серверных файлах репозитория; локальные копии LocalWP синхронизируем после проверок.
- Рабочие локальные адреса (`*.local`) не должны попадать в архив для хостинга. Перед выпуском сверять адрес WordPress и ссылки.
- После каждого изменения обновлять этот план и журнал. Решения, влияющие на публикацию и эксплуатацию, записывать явно.
- Минимальная проверка: синтаксис JS/PHP, формы четырёх типов, переходы между статическим сайтом и WordPress, мобильный экран, ошибка сети и ограничение повторных отправок.
