# Сайт ООО «АвиаТехноСофт»

Корпоративный сайт на HTML, CSS и JavaScript с PHP-обработчиком заявок и отдельным WordPress для новостей. Основа: ТЗ версии 2.0, ответы заказчика и содержание действующего сайта [aviatechnosoft.ru](https://www.aviatechnosoft.ru/). Дальнейшая работа над сайтом ведётся в этой папке.

## Структура

```text
index.html                    Каркас страницы, меню, подвал, модальное окно форм
assets/css/styles.css         Стили, сетка и адаптив
assets/js/data.js             Каталог, настройки форм, темы курса и описания продуктов
assets/js/components.js       Общие компоненты: кнопки, карточки, CTA, видео, обзор курса
assets/js/pages.js            Шаблоны главной и внутренних страниц
assets/js/forms.js            Формы и отправка заявки на сервер
api/lead.php                  PHP-обработчик заявок
assets/js/script.js           Запуск, маршруты и меню
assets/img/                   Локальные фотографии, постер и схема
assets/video/                 Демонстрация тренажёра
wordpress/ats-news/           Тема WordPress только для раздела новостей
wordpress/ats-news-theme.zip  Архив темы для установки через панель WordPress
wordpress/ats-static-site.zip Архив статической части для нового сайта
docs/wordpress-news-setup.md  Порядок тестового развёртывания новостей
docs/forms-local-testing.md   Проверка заявок в LocalWP и на хостинге
for_agent/site_plan.md        План этапов и открытые вопросы
for_agent/site_worklog.md     Решения и результаты проверок
ats.ru/aviatechnosoft.ru/      Архив старого сайта (не используется новой версией)
.prettierrc.json              Общие правила форматирования
.prettierignore               Исключение архива и бинарных материалов
docs/reference/               ТЗ и ответы заказчика
```

Сейчас главная и внутренние страницы выводятся через hash-маршруты (`#/product/pchelka`, `#/education` и т. д.). Для просмотра интерфейса достаточно открыть `index.html` в браузере; для отправки форм требуется PHP-сервер. Для локальной разработки удобнее запустить из корня проекта:

```powershell
python -m http.server 8080
```

После этого откройте `http://localhost:8080`. Этот сервер подходит только для просмотра интерфейса. Для проверки отправки форм используйте LocalWP и [инструкцию по формам](docs/forms-local-testing.md).

## Новости через WordPress

Для локального теста ссылки на новости в рабочих `index.html` и `assets/js/pages.js` ведут на `http://astru-news.local/`. Статический сайт LocalWP находится в `C:\Users\niokr\Local Sites\atsru\app\public`, а WordPress — в отдельном локальном сайте. Архив `wordpress/ats-static-site.zip` был собран для схемы хостинга с WordPress в `/news/` и сохраняет этот адрес. Перед следующим выпуском архива сверяйте ссылки с фактическим адресом WordPress. Порядок установки и проверки описан в [docs/wordpress-news-setup.md](docs/wordpress-news-setup.md).

## Как редактировать

- Каталог `products`, описания `productDetails`, темы `courseTopics` и настройки `formTitles` находятся в `assets/js/data.js`. Разметка страниц — в `assets/js/pages.js`, переиспользуемые блоки — в `assets/js/components.js`.
- Четыре типа заявок обслуживают `assets/js/forms.js` и `api/lead.php`; маршруты и меню — `assets/js/script.js`. Файлы подключаются с `defer` в порядке: данные → компоненты → страницы → формы → запуск. Используются обычные скрипты: интерфейс можно просматривать через `file://` без сборки, но формы работают только через сайт с PHP. Общие объявления доступны следующим скриптам; при добавлении функций избегайте повторных имён.
- Общие цвета заданы переменными в начале `assets/css/styles.css`. Адаптивные правила находятся в конце файла.
- Общая шапка, подвал и разметка формы находятся в `index.html`.
- Фотографии из копии старого сайта перенесены в `assets/img/` с понятными именами, видео — в `assets/video/trainer.mp4`. Новая версия не зависит от папки архива и внешнего сервера изображений. Шрифт Manrope пока загружается через Google Fonts с системным запасным шрифтом.
- Видео весит около 61 МБ и использует `preload="none"`, чтобы не загружаться до воспроизведения. Перед публикацией желательно подготовить сжатую веб-версию.
- Для единообразного оформления используйте Prettier 3 с настройками из `.prettierrc.json`: `npx prettier --write index.html "assets/js/*.js" assets/css/styles.css`. Для проверки замените `--write` на `--check`. Комментарий `/* HTML */` перед шаблонной строкой позволяет форматировать вложенный HTML.
- После изменения ссылок, маршрутов и форм проверьте главную, продуктовую страницу, мобильное меню и каждый из четырёх типов заявок на экране шириной около 390 и 1440 пикселей.

## Перед запуском публичного сайта

1. Получить брендбук, утверждённые фотографии изделий, технические характеристики и актуальные документы. Для фотографий занятий нужны права на публикацию; при их отсутствии использовать кадры без узнаваемых лиц.
2. Утвердить юридические тексты, политику обработки персональных данных и согласие для форм.
3. Настроить подтверждённый адрес отправителя и почтовый транспорт на хостинге, затем проверить реальную доставку заявок. Локальные тесты через Mailpit описаны в [docs/forms-local-testing.md](docs/forms-local-testing.md); заявки сейчас отправляются через PHP и не сохраняются в базе.
4. Добавить подтверждённые реквизиты и контакты, проверить формулировки страницы закупок.
5. Настроить аналитику, SEO-метаданные для каждой страницы, карту сайта и перенаправления со старых URL. Текущие hash-маршруты подходят для макета; для SEO-версии нужны отдельные URL страниц или маршрутизация на сервере.
6. Проверить доступность, адаптивность, скорость загрузки и работу форм в целевых браузерах.

Исходные требования находятся в `docs/reference/`. Если новое решение отличается от ТЗ или ответов заказчика, фиксируйте его в README или отдельной записи в `docs/` перед реализацией.

## Сравнение с локальной копией старого сайта — 4 октября 2026

Проверены главная, страницы комплекса и конструктора, новость, девять уроков и страницы тестирования в `ats.ru/aviatechnosoft.ru/`. Основа новой структуры уже охватывает продукты, образование, компанию и контакты. Закупки и документы выделены в самостоятельные разделы, поэтому дублировать старые блоки на главной не требуется.

### Что перенесено

- На страницу «Пчёлки» добавлены объяснение поворотного устройства, связь с симулятором и локальное видео из старой главной. Это показывает принцип работы, которого не хватало в кратком описании продукта.
- На страницу конструктора добавлены три сценария: сборка, подготовка к учебным полётам и применение с тренажёром.
- На страницу стенда добавлены конкретные учебные действия: моторы и регуляторы, FPV, UART, проверка схемы и диагностика.
- В раздел «Для образования» добавлен обзор девяти тем курса с запросом актуальной программы. Полные уроки и тест пока остаются в архиве.
- Фотографии продуктов и класса перенесены локально; исходный архив сохранён.

### Что стоит добавить следующим этапом

- Открытая библиотека уроков с навигацией и тестом полезна преподавателю. Перед переносом полного курса следует отредактировать материалы, проверить технические сведения и определить, что публикуется открыто, а что выдаётся с комплексом. Старые `test.php` и `test.js` не подключены к новой версии: это отдельная функциональность, требующая проверки.
- Новость о мастер-классе в Центре образования №164 в Уфе от 22 мая 2026 года можно разместить на странице компании после согласования текста и фотографий. Это материал о мероприятии, а не подтверждённый кейс внедрения. Отдельную ленту новостей стоит вводить при регулярных публикациях.
- Блоки «Комплектация», «Характеристики», «Совместимость» и «Дополнительное оборудование» нужны на продуктовых страницах после подтверждения актуальных данных. Старые цены 210 000 и 95 000 рублей не перенесены: в архиве прямо указано, что информация может изменяться.
- Telegram-бот указан только в старой новости. Добавить его в контакты стоит после подтверждения, что этот канал обслуживается компанией.

Утверждения старого сайта об исключительной уникальности, абсолютной безопасности, нормативном соответствии и реестровых записях не перенесены как установленные факты. Данная сверка оценивает содержание локального архива, а не актуальность этих заявлений. Формы новой версии отправляют заявки через PHP; встраивание старой Яндекс-формы и аналитики требует отдельного решения о рабочем процессе.
