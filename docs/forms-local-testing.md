# Проверка форм и писем

## Текущая схема

Все четыре формы основного сайта отправляются в `api/lead.php` на **том же домене**, что и `index.html`. WordPress раздела новостей для этого не нужен. PHP-обработчик проверяет тип формы и обязательные поля, ограничивает размер запроса и частоту отправки (не более 10 за 10 минут с одного IP), формирует текстовое письмо и вызывает `mail()`. Форма показывает ответ сервера и не открывает почтовую программу.

По умолчанию получатель — `aviatechnosoft@yandex.ru`. На `*.local` отправитель — `noreply@atsru.local`; LocalWP перехватывает это письмо в Mailpit. На внешнем домене адрес отправителя **обязателен**: задайте `ATS_LEAD_FROM` в окружении PHP или создайте `atsru-lead-config.php` рядом с публичным корнем сайта по образцу [lead-config.example.php](lead-config.example.php). Адрес `From` должен принадлежать домену, для которого настроена почтовая отправка. Файл настройки не загружайте в публичную папку и не добавляйте в Git.

## Локальный тест в LocalWP

1. В `C:\Users\niokr\Local Sites\atsru\app\public` должны находиться обновлённые `index.html`, `assets/` и `api/lead.php`.
2. Запустите сайт `atsru` в LocalWP и откройте `http://atsru.local/`.
3. Откройте любую форму, заполните вымышленными данными, отметьте согласие и нажмите «Отправить заявку». Должно появиться сообщение об успешной отправке.
4. В LocalWP для сайта **atsru** откройте **Tools → Mailpit → Open Mailpit**. Письмо должно появиться там; во внешний почтовый ящик оно не уйдёт.
5. Повторите для `f1` (КП), `f2` (расчёт класса), `f3` (демонстрация) и `f4` (документы). Проверьте тему письма и значения полей, в том числе дополнительные поля каждого типа.
6. Проверьте пустые обязательные поля, неверный email для документов и повторные отправки. При ошибке введённые данные должны остаться в форме для исправления.

## Проверка на тестовом хостинге

1. Загрузите `api/lead.php` вместе с обновлёнными `index.html` и `assets/`. PHP должен исполняться для этого сайта.
2. Задайте подтверждённый адрес `From` через окружение PHP или приватный файл рядом с публичным корнем. При необходимости измените получателя `ATS_LEAD_TO` либо `to` в приватном файле.
3. Убедитесь, что хостинг принимает почту от PHP и настроен для домена отправителя. Успех `mail()` означает принятие сообщения почтовой подсистемой, а не гарантированную доставку в ящик.
4. Выполните пробную отправку вымышленными данными и проверьте входящие и «Спам» реального ящика. Если письмо не приходит, проверьте почтовые журналы хостинга и настройте его SMTP/почтовый транспорт.

Не используйте настоящий сайт для тестов с персональными данными до утверждения политики обработки данных и текста согласия.
